# 踩坑与排错

> 按「踩坑频率」排序。新坑请补进来，写清**现象 → 对策**，别只写结论。

## 1. 环境

| 项 | 值 |
|---|---|
| 系统 | Windows 11；`terminal` 走 **Git Bash（MSYS）**，不是 PowerShell |
| node | v22.22.0 |
| Python | 3.12.13（命令是 `python`，不是 `python3`）+ numpy 2.5.3 / scipy 1.18.1 |
| git | 2.55.0.windows.5 |
| Chrome | `C:/Program Files/Google/Chrome/Application/chrome.exe`（备用 Edge：`C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`） |
| `gh` CLI | **未安装**，别用 `gh` |

`lib/chrome.js` 会自己找浏览器：先看环境变量 `CHROME` / `CHROME_PATH` / `CHROME_BIN`，
再找各平台常见安装路径（Windows 上 Chrome 找不到就退到 Edge），Linux 上还会用 `command -v` 找 PATH 里的名字
—— 所以 CI（ubuntu runner 自带 google-chrome）不用额外配置。

路径注意：本机 **MSYS 路径转换被禁用** —— `cd /c/Users/...` 可以用（bash 内建），
但**传给原生程序**（git / node / python）的路径要用 `C:/Users/...` 这种正斜杠原生形式，不能用 `/c/...`。

## 2. 已知坑（现象 → 对策）

| 坑 | 现象 | 对策 |
|---|---|---|
| **Clash 没开** | push 报 `Failed to connect … over proxy 127.0.0.1`；取消代理又 `Connection reset` | 先 `git ls-remote origin main` 探；不通就让用户开 Clash，**别反复重试** |
| **Steam++ 劫持 hosts** | github.com 被指到 127.0.0.1，直连与代理时通时不通 | 同上一行：先探再推；`git -c http.proxy= -c https.proxy= <cmd>` 纯直连重试 2~6 次通常能成 |
| **题库 JSON 不存在** | 克隆后直接跑 `crosscheck-*.py` 报文件找不到 | 先跑生成它的 node 脚本（顺序见 `docs/验证手册.md` 第 2 节） |
| **Pages 缓存延迟** | 推完立刻验，线上还是旧版 | 等 50~65 秒；验证请求带 `Cache-Control: no-cache` |
| **`curl` exit 23** | 写在 `&&` 链里会静默中断后续命令 | 串命令用 `;`，或改用 Python 发请求 |
| **`node --test test/unit/` 直接传目录** | 报 MODULE_NOT_FOUND（Node 22 把目录当模块入口找） | 用 `npm run test:unit`（它走 `test/run-all.js --unit`，自己列文件）；手跑就传文件列表 `node --test test/unit/*.test.js` |
| **`search_files` 偶发返回 0** | 明明存在的字符串搜不到 | 改用 `grep`（terminal）；或在 node 里直接读文件 |
| **`check-no-dp.js` 误伤** | 变量名写成 `dpXxx`（如 `dpOk`）、说明文字里出现那个已清零模块的中文名，都会命中 | 别用 `dp` 前缀命名变量；确实要在文档里讲解这条规则时，在该行末尾加标记 `check-no-dp:ignore`（只给说明文字用，别拿它藏真代码） |<!-- check-no-dp:ignore -->
| **LF/CRLF 警告** | `git add` 时刷一屏 `LF will be replaced by CRLF` | 噪声，忽略（sha256 比对时统一把 CRLF 归一化） |
| **无头 Chrome 默认 `prefers-reduced-motion: reduce`** | 断言「过渡挂在 transform 上」永远失败（量到的 `transitionProperty` 是 `none`），看起来像「动画没做」 | 样式表末尾有一条 `*{transition:none!important}` 兜底规则，headless 下会命中。断言动画前先 `Emulation.setEmulatedMedia` 显式声明 `no-preference`，断言完再恢复 |
| **以为 `setEmulatedMedia` 不触发 `matchMedia` change** | 怀疑「模拟系统深色」在无头下不生效 | 实测**会触发**（2026-09 验过：`init:false → change:true`）。所以 `shot.js` / `probe-color.js` / `audit.js` / `verify-ui.js` 里用 `setEmulatedMedia` 模拟系统外观的做法**不用改** —— 保持「模拟系统偏好」验的才是用户真实走的路径，别图省事直接改 `data-theme` |
| **远程审查的触摸目标假警** | 线上 `audit.js` 偶发报「N 个触摸目标 < 44px」，本地重跑为 0 | CDN 慢、元素还没渲染完就量了尺寸；现已对远程 URL 放宽等待（本地 1200ms / 远程 2600ms） |
| **`document.querySelectorAll(...).forEach`** | 老 WebView 上没有 forEach | `core/` 与 `web/` 里统一用 `Array.prototype.forEach.call(...)` |
| **注释里写 `z*/b` 这类片段** | 文件当场语法错误（`*/` 提前结束了块注释） | 注释里避免出现 `*/` 字面量，写成「最优值对右端项的偏导数」这类措辞 |
| **`index.html` 是构建产物** | 搜索时在 380 KB 产物里命中一堆重复结果，看起来像「源码里已经改了」 | 仓库里有一份 `.ignore`（ripgrep 用，不影响 git）：搜索时跳过 `index.html`、`preview/`、题库 JSON。要看产物请显式打开文件 |
| **手改 `index.html`** | 一下次 `npm run build` 覆盖掉，白改 | 永远只改 `src/`，然后 `npm run build`；CI 第一步就会抓「产物与源码不一致」 |

## 3. 调试的通用姿势

1. **先复现再改**：写一个最小复现脚本（几行 core 调用 + console.log），别在整页里猜。
   `node -e` 直接跑更快：
   ```bash
   node -e "const S=require('./src/core/simplex.js');console.log(JSON.stringify(S.simplexSolve({direction:'max',c:[1,1],constraints:[{coef:[1,1],rel:'<=',rhs:2}]})))"
   ```
2. **核心层没有 DOM**，所以算法问题在 node 里就能查；界面问题才需要浏览器。
3. **界面问题用 CDP 直接问页面**（用 `lib/chrome.js` 起会话，`sess.evl('…')` 取任意表达式），
   比截图看像素快得多。
4. **改完算法跑 `deep-snapshot` 前后 diff**（见 `docs/验证手册.md` 第 3 节）——
   这是「这次改动到底动了什么」最可靠的证据。
5. **不要让验证脚本「通过」而放弃断言**：历史上每一个真缺陷（影子价格符号、灵敏度区间过宽、
   对偶比值漏 M 项、0-1 上界未加入、割平面新增列顶位右端项、隐枚举最小化比反了）
   都是验证脚本抓出来的。失败时**先怀疑代码，再怀疑测试**；确认是测试写错了再改测试，并在注释里写原因。
