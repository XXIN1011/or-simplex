# 运输问题

入口为首页「运输问题」及 `#/transport`。支持最小运费 / 最大收益，供需可不平衡，可设置禁运路线，不设线路容量，不经过中转。

## 输入与经济含义

运输表中间输入单位运费或单位收益，右侧为各产地供应量，底部为各销地需求量。网页通过增减按钮编辑 0–8 行列；只添加产地或只添加销地也会显示对应表格，保留已填供应量 / 需求量，补齐另一侧后继续输入。实际求解需至少 1 个产地和 1 个销地，供需量可为零。供需为非负数；真实单位费用 / 收益可为负数。空白在网页中按零处理，核心 API 的空字符串则视为非法输入。

所有数值可用有限数字、小数、科学计数法或单个分数（例如 `-3/4`），分母不能为零；不解析算术表达式。**费用格填 `M` 表示禁运**（大 M 即该线路费用无穷大；大小写均可，旧标记 `X`、`×` 与 `禁运` 继续识别，允许首尾空白），恢复数字即重新可运；供需量及费率不接受禁运标记。未使用 `Infinity`、空白或超大费用模拟禁运，避免数值溢出或被误分配。输入区提供「载入禁运示例」，草稿及历史保留原标记。

- 供大于求：增加一个虚拟销地，其需求等于剩余总供应。每个产地运往虚拟销地的量表示该地产生的剩余供应，费用为该地单位处理费。
- 供小于求：增加一个虚拟产地，其供应等于总缺口。虚拟产地运往每个销地的量表示该销地缺货，费用为该地单位罚金。真实供应仍被全部分配。
- 默认虚拟费用零，表示忽略剩余处理 / 缺货的损失，虚拟运输不代表实物流动，也不产生收益。不平衡供需不会被描述为真实供需全部满足。
- 最大收益：真实格目标系数为收益，虚拟格原目标系数为处理费 / 罚金的负数。取**整个平衡模型全部可运格**的最大收益 `R`（含虚拟格，排除禁运格），各格以 `c′ᵢⱼ = R − cᵢⱼ` 转为最小化；全负收益时 R 也可为负，全禁运时约定 R = 0。平衡后总运量 `Q = sum(supply)` 固定，因此 `objective = R × Q − workingObjective`，等于真实总收益减损失。实现仍按原收益矩阵直接累计原目标，避免大数相减损失精度；Q 是运输量，不是指派问题的维数。
- 费用仅在对应虚拟行列存在时生效；供需平衡时没有虚拟费用。求解前平衡预览及求解后的最终表、模型表均展示虚拟格及费用。
- 自动增加的虚拟线路始终可用，其总量仅为原题供需总差，**不会为绕过禁运额外增加虚拟供需**。因此不平衡题也可能因禁运而无解；剩余量或缺货量仅在可行解中列为最终安排。

## 算法与确定性规则

1. 有禁运时，先在平衡模型的可运图上用辅助最大流检查供需可行性。无解返回 `infeasible`，显示最大可匹配量、未匹配总量及最小割瓶颈集合；不输出伪目标或伪最优运输表。总供应等于总需求不保证路线可达。
2. 最小元素法：在尚未固定且剩余供需均为正的**可运格**中选工作费用最小者，相同费用严格按行优先、列次之取下标最小者。无禁运时分配 `q=min(剩余供应, 剩余需求)`。有禁运时尝试强制分配 q，固定本格后检查剩余网络；如有缺额 D，将本格分配缩减为 `q−D`（可为 0）以保持可行。该公式来自运输供需割约束，取的是本格在剩余可行域中的最大可分配量。每格固定后不再重复分配。逐格最大化形成可行域极点，正量格构成森林；辅助流仅保护可行性，费用优化仍由位势法完成。
3. 用独立布尔矩阵记录基变量身份。按行列下标顺序，只将连接两个不同基分量的**可运格**作为零值基变量补入。可运图有 k 个连通分量时，形成含 `m+n−k` 条边的生成森林；无禁运时 k=1。孤立零供需结点也计入 k，禁运格绝不运输或入基；不把 epsilon 伪装成运输量。每个分量独立选一个结点令位势为 0，在基树上解 `u[i]+v[j]=c′[i][j]`；孤立结点位势也设 0。仅计算可运格的 `reduced[i][j]=c′[i][j]-u[i]-v[j]`。可运非基检验数均不小于负容差时，在数值容差内最优。
4. 采用 Bland 规则：负检验数非基格按下标最小者入基，基树加一条边得到唯一闭回路，从入基格起交替标 `+ / −`。负号格的最小真实运量为 `theta`；严格相等的最小值取下标最小格离基。正号加、负号减。`theta=0` 时只换基，其他零值基可继续保留。
5. 每次换基校验非负性、供需守恒、正运量必在基内、基边数与无环性，以及工作目标不增、变化等于 `theta * reducedEntering`。失败回退至上一轮可行方案。额外检测重复基和迭代上限，均明确停止，不误报最优。

多重最优不能仅凭「有一个零检验数」判断。求解器在零检验数残量网络中寻找可正量调整的回路，回退方向只能沿有正运量的格行走。找到后返回实际不同的运输方案及其 `cycle / theta / objective` 作为见证；可跨越单次退化换基不能直接显现的最优方案。全零供需或仅有退化换基不报告多重最优。多重最优也按浮点容差解释。

禁运格在所有费用表、最终方案、检验数表及过程表中都显示「禁运」，不显示伪造的零费用。闭回路和多重最优见证仅经过可运格。教学步骤会解释实际分配为何小于普通上限，包含被迫跳过的零分配格。

## 联动与动画学习

完整推导与单步学习共用同一步骤数据。最小元素分配不再逐帧播放，只在静态步骤表中标出所选格、并列候选、实际分配量与剩余供需；禁运保护步骤同时标出试分配后的瓶颈。短回路（不超过 6 格）从入基格开始，依次揭示每格的正负号及路径；最后一个节点只连到该格，到 θ 帧才补上闭合边并确定 θ 与离基格，新增线段单独描边，已画好的连线保持静态。最后同步显示 core 记录的调整后运量、基身份和工作目标变化（最大收益题先按最小化目标展示）。超过 6 格的长回路不逐格揭示：手机上一屏只放得下 1~2 列，逐帧要反复横向滚动去找下一格，因此改为「整条回路 → θ → 同步调整」三帧，首帧一次标全正负号。退化换基 θ=0 时运量一个都不变，末帧没有可视变化，直接与 θ 帧合并成一帧并写明只换基，不再空转一帧。位势法步骤用一张表同时显示检验数 Δ、行位势（表最右列）与列位势（表底行）。表格按教材版式排：每格左上角是费用角标（最大收益题在求解过程中为转换后费用，最后收益结算时为原收益），运量居中，基变量在运量外套一圈细方框，闭回路的正负号写在运量左侧并染色；连线只走格内留白，从费用角标下方的节点出发，沿行、列方向正交连接，中段带方向箭头；已标记的格按正负号分别着蓝色与警示色底，其余格暂时淡出。θ 帧给负号格的运量加荧光笔底以示比较对象，末帧只让真正改变的运量跳动一下，基身份与正负号配色不随之改色。不使用平滑插值伪造中间运输量。

播放需用户主动启动，提供暂停、上一帧、下一帧、重播及 0.6 / 1 / 1.8 秒帧间隔；同一结果只允许一处演示计时播放，到末帧停止。切换到其他学习步骤、折叠推导、切路由、页面隐藏或演示离开视口时暂停。系统 `prefers-reduced-motion: reduce` 下关闭计时播放、路径描边和流动光点，手动逐帧完整保留。重新求解或编辑题目时销毁旧计时器、事件与观察器，不保存或恢复播放状态。

手机窄屏只收紧格子，不改版式：输入格宽降到 44px 的最小触摸目标，390px 下产销平衡表与最终运输表能整表放下；更宽的表（含演示表）仍独立横向滚动，演示表固定行名与供应列并自动定位当前格。表标题是滚动容器外的 `tp-caption`，横向滚动时不会被裁掉；滑动提示在运输模块内只保留一条，不随每一步的过程表重复。回路连线走格内留白（费用角标下方），不穿过居中的运量。颜色之外还有“本次选择 / 并列候选 / 瓶颈产地 / 可达销地 / 序号与正负号”等文字标识。无解时直接在平衡表高亮瓶颈集合，不生成伪方案演示。

## 统一 API

```js
var or = require('./src');
var result = or.solveTransport({
  direction: 'max',
  cost: [[10, 20]],
  supply: [5],
  demand: [4, 4],
  surplusCost: 0,
  shortageCost: [2, 3]
}, { maxIterations: 1000 });
// status: optimal；realObjective: 90；penalty: 6；objective: 84
// shortage: [3, 0]；包含虚拟产地的 allocation: [[1,4],[3,0]]

var blocked = or.solveTransport({
  direction: 'min', cost: [[1, 2], [3, 'M']], supply: [5, 5], demand: [5, 5]
});
// objective: 25；allocation: [[0,5],[5,0]]
// 第一格普通上限 5，但保持可行只能分配 0，随后仍按最小元素顺序分配。
```

`surplusCost` 可为所有产地共用的标量或长度等于真实产地数的数组；`shortageCost` 同理对应真实销地。两者均默认零且须非负。API 接受原始分数字符串，不修改调用方对象。核心 API 最多 20×20；`maxIterations` 须为 0–10000 的整数，默认 1000，表示换基次数；即使设为 0，初始方案已最优仍可正确终止。

输入错误返回 `{ok:false,message}`。模型合法时返回 `ok:true`，必须继续检查 `status`：

| status | 含义 |
|---|---|
| `optimal` | 已通过当前数值容差下的最优性检验 |
| `infeasible` | 禁运路线下无法满足平衡模型的供需；`feasible:false`，`objective / allocation / basis:null`，无 `initial` |
| `iteration-limit` | 达到换基上限，当前可行方案不保证最优 |
| `cycling` | 基重复，停止防止浮点退化循环，不保证最优 |
| `numerical-error` | 数值或不变量校验失败，不能确认最优；检查 `feasible` |

主要返回字段：

| 字段 | 内容 |
|---|---|
| `model` | 原始供需 / 原矩阵、平衡后供需、原目标系数 `cost`、最小化工作费用 `working`、虚拟线路信息与容差；`allowed` 布尔矩阵标记可运性，`forbiddenCount / components / basisSize` 标记禁运数、可运图分量数及基边数。禁运格内部数值占位为 0，不代表零费用线路，必须以 `allowed` 为准 |
| `feasibility` | 无解时返回辅助最大流的 `deficit / remainingSupply / remainingDemand / cutRows / cutCols`；未匹配向量是一次辅助匹配的残余，不是唯一或最终缺货方案；割集合含虚拟结点时下标对应平衡模型 |
| `initial` | 最小元素初始可行方案的独立运量 / 基快照及原目标值 |
| `allocation`, `basis` | 最终或停止时平衡模型的运量矩阵与布尔基矩阵 |
| `model.maxReward`, `model.total` | 最大化转换常数 R 与平衡后总运量 Q；最小化题的 `maxReward` 为 0 |
| `objective`, `workingObjective` | 原目标与最小化工作目标；最大化时满足 `objective = R × Q − workingObjective` |
| `realObjective`, `penalty` | 真实线路目标与剩余 / 缺货损失 |
| `surplus`, `shortage` | 逐真实产地剩余量或逐真实销地缺货量，无对应虚拟线路时为 null |
| `potentials` | 最优时的行列位势、检验数及 `reducedTolerance` 逐格容差 |
| `multipleOptimal`, `alternative` | 多重最优标识与不同方案见证 |
| `steps` | `allocation / initial / potentials / pivot` 结构化步骤；每步含独立运量 / 基快照、原目标、工作目标和不变量检查结果 |

分配步骤额外包含所选格、候选并列格、实际分配量 `quantity`、普通上限 `proposedQuantity`、可行性保护标记 `guarded`、剩余供需，以及按普通上限试分配时的 `feasibilityDeficit / blockedCutRows / blockedCutCols`。初始步骤包含零值补基格；位势步骤含 `u / v / reduced / reducedTolerance / entering`（禁运格检验数内部占位 0，必须排除）；换基步骤含入基格、离基格、回路和正负号、调整前运量、`theta`、目标变化。结果渲染和单步学习均使用这些快照，不重新计算答案。

附加接口：`or.transport.validate(problem)` 返回平衡模型或输入错误；`balance(problem)` 仅检查供需平衡，费用尚未填完也可使用；`inspect(model,allocation,basis,partial)` 检查方案不变量（主要用于验证）。

最大收益题的分配表、初始方案表及闭回路演示的费用角标统一显示 `working`（转换后费用 c′），过程目标统一显示 `workingObjective`；位势和检验数也使用同一转换模型。换基快照额外提供 `workingObjectiveBefore / workingObjectiveAfter`，供演示逐帧读取。逐步推导最后增加收益还原步骤，才使用原收益矩阵按最终运量结算净收益；原始输入、模型转换前的矩阵及最终结果摘要仍保留原收益语义。

演示使用的分配步骤还包含独立的 `beforeAllocation / beforeBasis / beforeRemainingSupply / beforeRemainingDemand / objectiveBefore` 快照；换基步骤也包含 `beforeBasis`。这些对象不与调整后的方案共用数组，DOM 层只读其值，不进行运输量计算。

## 模块边界

- `src/core/transport-model.js`：数字校验、供需平衡、费用方向、公共矩阵及不变量。
- `src/core/transport-initial.js`：最小元素分配与无环零值补基。
- `src/core/transport-flow.js`：禁运供需可行性检查、分配保护与最小割见证，无费用优化职责。
- `src/core/transport-modi.js`：位势、基树路径、闭回路、Bland 换基及多重最优。
- `src/core/transport.js`：统一求解 API、结构化快照及原目标读出。
- `src/web/transport-ui.js`：输入、即时状态、失效逻辑、示例 / 草稿 / 历史接入。
- `src/web/transport-report.js`：结果优先展示、推导与共用单步阅读组件。
- `src/web/transport-table.js`：静态表、选中 / 并列 / 瓶颈及回路标记的统一渲染。
- `src/web/transport-player.js`：闭回路演示阶段、控件、SVG 路径、减少动态效果与生命周期清理，仅消费 core 数据。

核心层均为 ES5，零 DOM / IO；浏览器层不实现求解公式；构建自动收集新模块，无新增运行时依赖，根目录 `index.html` 仍为离线单文件。

## 数值边界与验证

使用 JavaScript IEEE 754 双精度，分数会转为浮点数，并非精确有理数运算。供需差在总规模 `1e-12` 内时作为求和舍入误差，在最大需求格校正，保留原供需并在界面说明。守恒容差为总量规模的 `1e-10`；逐格费用检验容差为参与运算的费用及行列位势绝对值之和乘 `32 * machineEpsilon`，避免一条无关高费用路线吞掉其他格的改善。换基目标变化的校验使用规模相对容差。极端量级差可能丢失低位信息，建议统一数量与费用单位；溢出 / 坏基会明确停止。显示遵循现有分数优先、约六位有效数字格式，极小非零量保留科学记数形式。

禁运辅助流按每个结点自身供需量乘 `32 * machineEpsilon * (m+n)` 检查残余，避免其他行的大量级掩盖完全不可达的微小供需。分配保护的 `q−D` 按本次 q 的同级舍入界归零或贴齐 q，并忽略相对各行列原供需量的舍入尾差，防止虚假的极小正量形成回路。这仍是数值容差求解；极端混合量级下不保证精确保留低位小量。
