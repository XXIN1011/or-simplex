# 架构与约定

> 这份文档讲**结构**：东西放在哪、为什么这么分、加东西要动几处。
> 想知道「改完怎么验证」看 `docs/验证手册.md`，「推送上线」看 `docs/推送与部署.md`，
> 「踩过的坑」看 `docs/踩坑与排错.md`。

## 1. 分层

```
src/template.html   HTML 骨架（样式与脚本均由构建内联）
src/styles/         tokens / components / theme / workspace 四层样式
src/core/           领域层：零 DOM、零 IO，Node 里可直接 require 与测试
src/web/            表现层：只碰 DOM；算数一律调 core/
src/build.js        迷你 CommonJS 打包器：src/ → 仓库根 index.html
src/cli.js          命令行入口；src/index.js 是库出口（package.json 的 main）
lib/                开发工具（不进产物）：无头浏览器启动器、安静模式
test/               单元 / 算法回归（含 scipy 对拍）/ UI 回归
tools/              构建-验证-发布用的小工具
```

**依赖方向单向**：`web → core`；`core` 内部 `simplex / parse / scenario / integer / assignment → format / util / model → errors`，
`model.js` 不依赖任何东西。**不允许环，也不允许靠 `window.xxx` 互相调用**——
跨模块的全局挂载已全部清除，`table-render.js`、`input-panel.js`、`dom.js` 就是当年那些全局挂载的替代品。

`lib/` 与 `tools/` 是**开发工具**，不进单文件产物（打包器只扫 `src/core` 与 `src/web`），
所以它们可以用现代 JS；`src/core` 与 `src/web` 必须 ES5（见第 4 节）。

## 2. 构建（单文件产物怎么来的）

`src/build.js` 是一个约 100 行的迷你 CommonJS 打包器（零依赖）：

1. 读 `src/template.html`，包含 `/*__BUNDLE__*/` 与 `/*__STYLES__*/` 两个占位符；样式按固定层次内联；
2. 把 `src/core/*.js` 与 `src/web/*.js` 逐个包成
   `__define__('<路径>', function (module, exports, require) { …源码… })`；
   —— 文件名自动扫描，**不用手工登记**（但 `src/web/boot.js` 要按顺序 `require` 它，否则界面不初始化）；
3. 拼上一个约 30 行的 `__require__` 注册表，支持 `./x.js`、`../y.js` 相对解析；
4. 末尾 `__require__('src/web/boot.js')` 启动；
5. 写入**仓库根**的 `index.html`（GitHub Pages 的发布目录就是仓库根，入口只能是这里）。

所以浏览器里跑的仍是一份普通 `<script>`：**离线、`file://` 双击都能用**。
不要改成 ES module（`import` 在单文件里 shim 不了，会同时破坏离线与 `file://`）。

**产物必须与源码一起提交**：改了 `src/` 就要 `npm run build`。
`node tools/status.js` 会重建一次并对比，判断产物是不是最新的；
CI 里第一步就是 `node src/build.js && git diff --exit-code -- index.html`，
漏构建会直接红。

> 哈希变化**不代表**构建坏了（源码改了哈希当然会变）。它只在「同一份源码构建两次」时
> 用来验可复现性：`npm run build` 两次，`git diff index.html` 应为空。

## 3. 加东西要动几处

### 加一个模块（例如再加一个算法模块）

| # | 改哪里 | 说明 |
|---|---|---|
| 1 | `src/core/xxx.js` | 算法实现，零 DOM；需要的部件先从 `core/simplex.js` 找 |
| 2 | `src/web/xxx-ui.js` | 界面：`require` core 层，`module.exports` 导出公开函数 |
| 3 | `src/web/boot.js` | 按顺序 `require('./xxx-ui.js')`（漏了就「页面无反应」） |
| 4 | `src/template.html` | 加 `<div class="mod" id="mod-xxx">` 容器 + 首页加一张 `<a class="modcard" href="#/xxx">` 卡片 |
| 5 | 输入区 | 如果有输入表，`<div id="xxxPanel"></div>` 挂载点 + 界面里 `createInputPanel({ mount: 'xxxPanel', … })` |
| 6 | 想让入口常驻底栏 | 才再往 `<nav class="tabbar">` 加 `<a href="#/xxx" data-m="xxx">`（现在的底栏只有首页 + 设置；加了要同步改 `verify-ui.js` 里那条「底栏只剩首页/设置」的断言） |

**不再需要动手的地方**（2026-09 收口后）：

- `src/web/router.js` 的模块清单是**从模板读的**（`.mod` 容器），不用登记；
- 输入区外壳（方向段控 + 输入表 + 增减按钮）由 `input-panel.js` 的 `buildChrome()` 生成，
  四个模块共用一份，模板里只留挂载点；
- `esc()` / `$()` / `subs()` 在 `src/web/dom.js` 里只有一份，别再抄进新文件。

改完跑 `node tools/check-registry.js`：它静态检查「JS 取的 id 在不在模板里 / 路由有没有容器 /
界面文件有没有被 boot.js 接线 / 模板有没有重复 id」，一条命令几十毫秒。

### 加一个新算法（对偶单纯形 / 两阶段法 / 新的整数规划方法）

`core/simplex.js` 已把迭代内核拆成 4 个可替换部件，**加算法不用改它一行数值代码**：

```js
const { solveStandardForm, selectEnteringDantzig, ratioTest, pivot, readOut } = require('./core/simplex.js');
const { parseProblem } = require('./core/parse.js');

const form = parseProblem(problem).form;
const res  = solveStandardForm(form, { selectEntering: myRule, maxIter: 500 });
```

| 函数 | 作用 |
|---|---|
| `selectEnteringDantzig(form)` | 默认入基规则：最大正检验数（并列取最小下标） |
| `ratioTest(form, e)` | 最小比值规则，返回 `{ratios, r, minRatio}`（`r = -1` 表示该列无正系数） |
| `pivot(form, r, e)` | 枢轴变换（就地改 `form.rows/obj/basis`），返回枢轴元素原值 |
| `readOut(form, steps, status)` | 从终止基读出解 / 结论 / 对偶解 / 灵敏度区间 |
| `solveStandardForm(form, opts)` | 主循环，支持 `opts.selectEntering` 与 `opts.maxIter` |

`core/scenario-tableau.js`（对偶单纯形）、`core/scenario-param.js`（参数行走）与 `core/integer-cut.js`（割平面调回可行）就是这么复用内核的。
**改算法前先看看是不是已经有现成部件**，别再造第二份枢轴。

### 加一个界面验证脚本（截图 / 探测）

用 `lib/chrome.js`，别再造一份 CDP 管线：

```js
const chrome = require('../../lib/chrome.js');          // 按自己层级调整
const sess = await chrome.launch({ url: chrome.resolveTarget('index.html#/sens').pageUrl, captureErrors: true });
const v = await sess.evl('document.title');
await sess.saveShot('preview/xxx.png');
await sess.close();
```

它负责：找 Chrome（`CHROME` 环境变量 → Windows/macOS/Linux 常见路径 → PATH）、
起无头进程、等调试端口、开 target、模拟手机视口、注入 `window.__errors`、收尾清理临时 profile。
脚本想安静点就在开头 `const q = quiet.begin('名字')`，结尾 `q.end(ok, '一行结论')` ——
带 `--quiet` 时只打印一行并写日志到 `preview/logs/`。

## 4. 代码约定（破坏它们就等于回退到重构前的状态）

1. **`core/` 与 `web/` 统一 ES5**：`var`、`Array.prototype.forEach.call`，不用箭头函数 / `let` / `const` / 模板串。
   原因：这些文件原样打包进单文件页面，ES5 在任何年代久远的 WebView 上都不会翻车。
   `test/`、`tools/`、`lib/` 是 Node 跑的，可以用现代语法。
2. **零依赖**：不引 CDN、不装 npm 包（`package.json` 刻意没有 dependencies）。
   算法在项目内实现，便于展示完整过程、独立验证和跨平台复用。
3. **算法只有一份实现**：迭代内核只有 `core/simplex.js`，其余模块用
   `ratioTest` / `pivot` / `solveStandardForm` / `readOut` / `sensTableau` 复用。
   `core/scenario.js` 里那份「对偶单纯形一步 + 读解」是刻意保留的例外（判定顺序与文案不同），
   改它之前先读它开头的注释。
4. **分层不许越界**：`core/` 不许出现 `document` / `window` / 文件读写；`web/` 不许内联算法公式。
5. **模块之间只走公开接口**：要别的功能就 `require` 它导出的函数，别再挂 `window.xxx`。
6. **中文注释，解释「为什么」**，尤其是退化、边界、历史缺陷的分支。
7. **提交信息用中文**：说清「改了什么 + 为什么」，修算法缺陷要写根因。
8. **手机优先**：触摸目标 ≥ 44×44、正文对比度 ≥ 4.5:1、宽表格要有横向滚动提示
   （`.scroll` 容器 + `addScrollHints`）。
9. **不要把「没跑完」说成「最优」**：分枝定界有结点上限、隐枚举有规模上限，
   触顶必须在界面上写明「目前最好，不保证全局最优」。这是本项目的底线。

## 5. 视觉主题（系统工具风格 + 实色分组面板）

- 主题一律走 `html[data-theme]`（`settings-ui.js` 解析系统偏好后写属性），
  **不要写回 `@media (prefers-color-scheme: dark)`**：三档设置里「系统是深色、用户要浅色」
  媒体查询表达不了，而且同权重按源码顺序决胜，深色配色会被迫写两份、早晚改漏一处。
- 视觉参考 Apple 设置与系统工具，使用实色面板、细线分组、系统字体与蓝色主操作；具体令牌和组件规则见 `DESIGN.md`。
- 页面基质色保留在 `html`，`body` 透明。`verify-ui.js` 的明暗背景断言读取 `documentElement`；不要绕过主题令牌另写一套背景色。
- 表格、结果和说明使用稳定承载面；焦点、禁用、选中、入基列、出基行和枢轴格保持明确的语义区分。
- `<meta name="theme-color">` 只留一条、由 JS 改写，不要加回带 `media` 属性的两条。
- 量色彩用 `tools/visual/shot-vp.js`（截视口图，fixed 层位置才对）+ `tools/visual/probe-color.js`
  （量截图上的真实像素，补充 `getComputedStyle` 的近似计算），
  再用 `tools/visual/measure-contrast.py` 算对比度。

## 6. 按职责拆分的实现

- 运输问题按 `transport-model / transport-flow / transport-initial / transport-modi / transport` 拆分校验、禁运可行性网络、初始基、位势与闭回路和统一 API；`transport-ui / transport-report` 分开输入与过程渲染，细节见 [运输问题](运输问题.md)。
- 运输表及演示分别复用 `web/transport-table` 和 `web/transport-player`。演示只读 core 快照，前后运量、基身份及剩余供需均由 core 提供，不在 DOM 层重算；每次结果失效须调用播放器清理函数，移除计时器、观察器与事件。

- `integer.js` 保留稳定入口；`integer-common.js` 管理类型、界与松弛，`integer-branch.js / integer-cut.js / integer-enum.js` 分别实现三种整数算法。
- `scenario.js` 保留稳定入口；`scenario-tableau.js` 管理建表与迭代，`scenario-changes.js` 管理条件变更，`scenario-param.js` 管理参数区间与行走。
- `simplex-report.js / integer-report.js` 负责结果生成，模块界面文件负责输入与事件；`input-guide.js / examples.js` 共用输入引导，`result-layout.js` 共用章节跳转。
- `src/styles/tokens.css` 定义基础主题令牌，`components.css` 定义布局与组件，`theme.css` 定义实色主题和交互状态，`workspace.css` 定义输入引导与正文表面。构建后的页面仍不请求外部 CSS。

修改实现时保留这些公开入口和单向依赖；拆分不得复制枢轴或其他算法内核。

## 7. 当前题目保存与结果阅读

- `web/draft.js` 统一管理每模块一份输入草稿，使用 `or-simplex-draft:<模块>` 的 localStorage 键及版本 1 的数据封装。恢复前校验维度、关系符和变量类型；无效或不可访问的存储只显示提示，不中断页面启动与求解。
- `input-panel.js` 的 `getDraft()` 返回未解析的原始输入，`getProblem()` 仍负责在求解前转成数字；不要用求解对象代替草稿，否则未完成的数字会丢失。整数类型、指派矩阵和灵敏度场景由各界面通过草稿接口补充。
- 监听输入区冒泡的 input/change/click，在控件更新后立即保存。清空题目只移除本模块的键；不能使用 `localStorage.clear()`，也不保存结果或自动求解。灵敏度场景先暂存，用户重新求基准解后再恢复；修改基准题会丢弃旧场景。
- 单纯形结果主线是结论、标准化与迭代，对偶和灵敏度区间放在末尾的折叠扩展分析。各模块的过程分组都用 `result-work`，章节跳转复用 `result-layout.js` 并自动展开祖先 details。
- `web/study-view.js` 复用算法输出的步骤生成完整/单步两种阅读方式，由 `result-layout.js` 初始化。每组独立维护步骤位置，不重新求解、不写入草稿；指派用 `data-study-part` 标记轮次，单步时展开当前轮，返回完整过程时恢复原折叠状态。
- `core/number-input.js` 是唯一的数字/分数解析入口。只接受完整数字或一个分子/分母，不使用 eval 或部分解析；未完成输入和零分母返回 NaN，仍由各模块原校验流程处理。输入框保留分数原文，`getProblem()` 才转换为数值。
