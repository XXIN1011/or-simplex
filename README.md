# 运筹学计算器（Operations Research Calculator）

一个面向**教学**的运筹学求解器，覆盖**线性规划（大 M 法单纯形法）**、**灵敏度分析**、**整数规划**、**指派问题**与**运输问题**。
与常见的“只给答案”的求解器不同，它把算法的**每一步中间过程完整摊开**给学生看：
单纯形法的每一张迭代表、灵敏度分析在原最优表上的判断、整数规划四种方法各自的过程。

手机优先设计，单文件、零依赖、可离线；同时它也是一个**标准的 Node 工程**：
算法层是可以 `require` 的库，还带一个命令行入口。

## 功能

**首页**列出五个模块：**单纯形法** / **灵敏度分析** / **整数规划** / **指派问题** / **运输问题**，各用一条 hash 路由
（`#/simplex`、`#/sens`、`#/ip`、`#/assign`、`#/transport`），手机上刷新、后退、加到桌面都能正常工作。

底部标签栏只放两个常驻入口：**首页**（`#/`）与**设置**（`#/settings`）。五个算法模块从
首页的卡片进入，模块页顶部都有「← 返回首页」。

### 单纯形法

- 支持 `max` / `min` 以及 `≤` / `≥` / `=` 任意组合的约束
- 自动识别并处理三类边界情况：**无可行解**、**无界解**、**多重最优解**
- 负数右端项自动整行取负并翻转关系符（保证初始基可行）
- `min` 问题自动按 `max` 求解后还原目标值

### 灵敏度分析（场景式）

先解出基准最优解，再选择一种条件变化，在原最优表上判断、继续迭代。

| 分析场景 | 前置判断 | 判断不通过时 |
|---|---|---|
| 改右端项 | 重算 `x′_B = B⁻¹b′` | **对偶单纯形法** |
| 改目标系数（非基变量部分） | 只重算 `σ′_j = c′_j − z_j` | 原始单纯形法 |
| 改技术系数（x_j 非基的列） | 只重算该列的 `σ′_j = c_j − c_B·(B⁻¹P′_j)` | 原始单纯形法 |
| 增加一个变量 | 新变量的检验数 `σ′ = c′ − c_B·P` | 原始单纯形法 |
| 改目标系数（基变量部分） | **σ 整行重算**：`σ′ⱼ = σⱼ − Δ·(B⁻¹Pⱼ)_k` | 原始单纯形法 |
| 改技术系数（x_j 是基的列） | **整张表重算**（B 与 B⁻¹ 都变） | 原始/对偶单纯形法，两者同坏时重新求解 |
| 增加一个约束 | 当前最优解是否满足它 | **对偶单纯形法** |
| 参数线性规划（变量系数） | `σⱼ(λ) = σⱼ + λ·τⱼ ≤ 0` 交成 λ 区间 | 区间端点处原始单纯形法换基 |
| 参数线性规划（右边系数） | `x_B(λ) = B⁻¹b + λ·B⁻¹e ≥ 0` 交成 λ 区间 | 区间端点处对偶单纯形法换基 |

> 系数变化按**基变量与非基变量**分别判断：非基变量的目标系数只影响它自己那一列的
> 检验数；基变量的目标系数进入 `c_B`，而 `zⱼ = c_B·(B⁻¹Pⱼ)` 每一项都含 `c_B`，
> 所以 **σ 的整行都要重算**。

输出沿用单纯形法那套迭代表（含三重高亮与逐步讲解），所以「新最优解怎么来的」
一目了然。

**边界与退化情形也如实交代，不硬算：**

- 改完之后原最优基的**基矩阵变成奇异**（列线性相关）→ 说明它不再能充当一组基，改为从标准初始基重新求解
- **可行性与最优性同时被破坏** → 原始单纯形法要求右端项非负、对偶单纯形法要求检验数非正，两种局部迭代法都用不上，需要重新求解
- 参数线性规划中 **右端项在 λ 范围内会变号** → 建表时的「整行取负」会随之翻转，模块在该临界值处停下并提示，越界部分请手工复核
- 参数线性规划中，基里残留的人工变量必须**恰好为 0**（它一旦随 λ 变成非零，就说明原约束没有被真正满足），所以该基的 λ 区间应当**钉成一点**。这里踩了第二层坑：同一个基会被「向上」「向下」两次行走各记录一遍，而这条限制最初只夹了当前行走方向 —— 另一个方向记下来的那份区间仍然过宽，合并时取的恰好是它，于是把**无可行解**的 λ 区间当成最优区间报了出去。表现是随机对拍**约一半的运行会失败**（且永远锁定在同一道含人工变量的题上），修法是两个方向都钉、并在钉完后立刻判一次空区间。

### 整数规划

输入**任意**整数规划题（每个变量分别指定 连续 / 整数 / 0-1），自动判定四种方法各自能不能用，
**能用的把完整计算过程全部输出，不能用的一律不输出、只说明为什么**。

| 方法 | 适用条件 | 输出内容 |
|---|---|---|
| 图解法 | 恰好 2 个决策变量、且有可行域 | 可行域 + **整数格点** + 松弛最优解（橙点）与整数最优解（绿点）对比 |
| 分枝定界法 | 松弛问题有最优解（几乎总是） | 逐结点的附加约束、松弛解（非整数分量加粗）、界、以及「为什么分枝 / 为什么剪掉」；每个结点还可展开看它自己的单纯形迭代表 |
| 割平面法 | 全整数 + 全 ≤ 约束 + 数据为整数（当前实现支持的标准形式） | **Gomory 割的逐刀推导**（从哪一行读出来、小数部分、割的系数），以及加割后用对偶单纯形法把表调回可行的每一步 |
| 隐枚举法 | **所有**变量都是 0-1 | 标准化（负目标系数的 x_j = 1−y_j 替换）+ 完整的枚举表：每个点的目标值、**过滤条件**是否通过、逐条约束的检查结果与结论 |

**规模保护**：隐枚举要枚举 2ⁿ 个点。引擎默认对 ≤ 36 个变量的题目都能算，但**输出**会按规模收口 ——
枚举点超过 4096 个时不再默认全跑，而是提示按用户勾选的方法输出（正是为了避免卡顿）；
枚举表超过 300 行只铺「通过过滤条件、真正检查过约束」的那些点。

**不会把「没跑完」说成「最优」**：分枝定界有结点上限（300）。一旦触顶，结论会明确写成
「目前找到的最好整数解，不能保证是全局最优」，而不是照旧标「最优解」。

### 运输问题（最小元素法 + 位势法）

- 用运输表输入：中间是单位运费 / 收益，右侧供应，底部需求；实时提示供需平衡。支持整数、小数、科学计数法与分数，空白按 0。
- 只用**最小元素法**生成初始可行方案，再以**位势法和闭回路调整**求最优；示例从初始费用 430 调整至最优费用 360。
- 供大于求增加虚拟销地，供小于求增加虚拟产地。虚拟行列、费用与逐产地剩余 / 逐销地缺货均可见；支持逐产地剩余处理费和逐销地缺货罚金，默认零表示忽略该损失。
- 最大收益通过整体取负转成最小化，最后还原**净收益**（真实收益减去处理费或罚金），同时列出真实线路收益与费用。
- 先展示最终方案与目标，再提供最小元素选择、分配量、剩余供需、零值补基、位势、检验数、闭回路正负号、调整量及目标变化；支持完整过程 / 单步学习。
- 复用示例、原文草稿、历史记录、三档主题和手机横向数表。修改费用、供需、罚金、方向或规模后，旧结果立即失效。
- 核心 `solveTransport(problem, options)` 无 DOM / IO，运量与基身份独立，确定性 Bland 换基与重复基保护；未收敛和数值异常不会报最优。

费用格填 `M` 可设禁运（大 M 表示该线路费用无穷大；旧标记 `X`、`×` 与“禁运”仍识别），输入区有禁运示例。禁运格不运输、不入基；先检查路线可行性，最小元素分配附带防堵路保护，再用位势法求最优。无解时给出供需瓶颈，互不连通的可运区域分别求位势。禁运标记可保存到草稿和历史。

推导中，最小元素分配以静态表展示所选格、并列候选和剩余供需；闭回路可逐帧播放，按顺序标记正负号，再展示 θ、换基和费用变化。最后一个节点只连到该格，下一帧才补闭合边，新增线段单独描边，已画好的连线保持静态；超过 6 格的长回路一次标全正负号（手机上逐格揭示要反复横向滚动），退化换基 θ=0 不单独占“同步调整”帧。位势法的行位势 u 放表最右列、列位势 v 放表底行。支持暂停、回退、重播及帧间隔选择；系统减少动态效果时保留手动逐帧。手机宽表会定位当前格，行名与供应列保持可见。禁运保护及无解瓶颈也会在表中标记。

网页最多 8×8，核心 API 最多 20×20，默认最多 1000 次换基。分数解析为 JavaScript 双精度数，不是任意精度有理数运算；暂不支持线路容量和中转。模型约定、API、状态与数值边界见 [运输模块说明](docs/运输问题.md)。

### 指派问题（匈牙利法）

输入一个费用（或收益）矩阵（行 = 人员，列 = 工作），输出**每一步迭代**：

| 步骤 | 内容 |
|---|---|
| ① 行归约 | 每行减去本行最小元素 |
| ② 列归约 | 每列减去本列最小元素 |
| ③ 试指派 | 圈出互不同行同列的 0（独立零元素）；贪心圈不动时用增广链把它补成最多 |
| ④ 覆盖线 | 打勾法：没打勾的行画横线、打勾的列画竖线；条数 = 最多独立零元素个数（König 定理） |
| ⑤ 矩阵调整 | θ = 未覆盖区域的最小元素；未覆盖的减 θ、被两条线交叉覆盖的加 θ，回到 ③ |

圈出的 0 达到 n（方阵阶数）时结束，圈到的那 n 个格子就是最优指派。三种非标准情形都在
算法里处理：

- **最大化**：`b_ij = M − c_ij`（M 取矩阵最大元素）转成最小化，再用 `z = n·M − Σb` 还原成
  最大总收益；界面上把「原系数矩阵 → 进入匈牙利法的矩阵」并列写出来。
- **人数与工作数不等**：补虚拟人员 / 虚拟工作（费用取 0），谁被派到虚拟工作就表示谁没有活干。
- **禁止指派**：单元格里填 `×`（JSON 里写 `null`），内部按无穷大处理，该格永远不会被指派；
  凑不出完整指派时给「无可行解」并说明是哪一行 / 哪一列卡住了。

0 行 0 列也照算（结论是「空问题，z = 0」），不设「至少要有 1 行」这类人为下限。

### 教学特性

| 特性 | 说明 |
|---|---|
| 完整单纯形表 | 每一轮迭代的系数矩阵，含松弛变量 `s`、人工变量 `a` |
| 符号化大 M | 检验数以符号形式显示为 `7M - 4` 这类形式，而非近似大数 |
| 三重高亮 | 入基列（蓝）、出基行（橙）、枢轴元素（黄底橙边） |
| 自动讲解 | 每张表下自动生成 `① 选入基 → ② 比值检验（列出每个 θ 的计算）→ ③ 枢轴变换` |
| 单步学习 | 迭代过程可在「完整过程 / 单步学习」之间切换；上一步、下一步及步骤选择器共用已有表格、高亮与讲解，指派步骤支持跨轮次跳转 |
| 输入体验 | 空白按 0 计算；支持小数、科学计数法（如 `1e3`）、数学负号 `−` 和分数（如 `1/2`、`-3/4`）。分母为零、不完整分数、逗号和非法字符会被标注并拒绝求解。修改题目后，旧结果会标记失效或清除 |
| 标准化 | 求解前先展示「原问题 → 标准型」的完整变换：min 转 max、加减松弛/剩余变量、引入人工变量 |
| 图解法 | 2 变量时自动画出可行域、目标函数等值线与最优顶点（内联 SVG） |
| 对偶解 | 由最终基算出影子价格 `y = c_B·B⁻¹`，并标出哪些约束还有余量 |
| 灵敏度区间 | 保持最优基不变时 c 与 b 的允许变化范围；基变量额外给出「c 每 +1，z* 变化多少」 |
| 参数线性规划 | 含参数 λ 时给出一张「λ 区间 → 最优基 → x(λ) → z(λ)」的分段表 |
| 退化提示 | 最小比值 θ = 0 时明确指出这一步不会改善目标值 |
| 符号说明 | 可折叠地解释 x/s/a、σ、M、基变量、z 的含义 |
| 显示模式 | 设置页三档可选：**跟随系统**（默认）/ **浅色** / **深色**；选择记在本机，切换即时生效 |
| 溢出提示 | 表格超宽时提示可左右滑动 |

## 使用

**网页版**：直接用浏览器打开 `index.html`，或访问线上版本

**https://xxin1011.github.io/or-simplex/**

在手机上可添加至桌面快捷打开；离线使用请保存完整的 HTML 文件。

**当库用**（Node ≥ 18）：

```js
const or = require('or-simplex');                 // 仓库内也可 require('./src/index.js')

const res = or.solve({
  direction: 'max',
  c: [2, 3],
  constraints: [
    { coef: [1, 2], rel: '<=', rhs: 8 },
    { coef: [4, 0], rel: '<=', rhs: 16 }
  ]
});
// res.status === 'optimal'，res.objective === 14，res.solution === [4, 2]
// res.steps 是每一张单纯形表（含入基/出基/θ/枢轴），res.dual 是影子价格
// res.sensitivity 是 c 与 b 的允许变化区间

console.log(or.format.report(res, problem));      // 纯文本完整报告
or.solveInteger({ ...problem, vtypes: ['int', 'int'] });   // 整数规划
or.analyzeScenario(problem, scenario);                     // 场景式灵敏度分析
or.analyzeParametric(problem, scenario);                   // 参数线性规划
```

只要算法层也可以按模块取：

```js
const { simplexSolve } = require('or-simplex/src/core/simplex.js');
const { fmtNum } = require('or-simplex/src/core/format.js');
```

**命令行**：

```bash
node src/cli.js '{"direction":"max","c":[2,3],"constraints":[{"coef":[1,2],"rel":"<=","rhs":8}]}'
node src/cli.js --file 题目.json          # 从文件读
cat 题目.json | node src/cli.js           # 从标准输入读
node src/cli.js 题目.json --json          # 直接输出结果 JSON（脚本里接管道）
node src/cli.js 题目.json --no-tables     # 只要标准型 + 结论 + 对偶 + 灵敏度
node src/cli.js 题目.json --integer       # 按整数规划求解（四种方法的适用性与结论）
```

退出码：`0` = 得到最优解；`1` = 无界 / 无可行解 / 未收敛 / 输入非法（脚本里可直接判）。

## 代码结构

算法与界面彻底分开：`src/core/` **零 DOM、零 IO**，Node 里可直接 `require`；`src/web/` 只碰 DOM。
两层之间靠显式 `require` 交互，不再有跨文件的全局变量。

```
index.html      成品（单文件，构建产物）—— 必须留在根，它是 GitHub Pages 的入口
src/core/       领域层：errors util model parse simplex sensitivity scenario integer assignment format
src/web/        表现层：boot（唯一入口） router dom input-panel table-render graph settings-ui
                以及四个模块界面 ui / sens-ui / ip-ui / assign-ui
src/build.js    构建：迷你打包器，把 core/ + web/ 打成单文件 index.html
src/template.html  HTML 骨架，构建时内联样式与脚本
src/styles/     tokens / components / theme / workspace 四层 CSS
src/cli.js src/index.js   命令行入口 / 库的统一出口
lib/            开发工具（不进产物）：chrome.js 无头浏览器启动器、quiet.js 静默模式
test/           验证：unit（单元）/ algorithm（算法回归 + scipy 对拍）/ ui（无头浏览器）
                test/lib/rng.js 是可复现随机源（固定种子，--seed=N 换批次）
tools/          构建-验证-发布用的小工具：status / check-registry / check-no-dp / dom-snapshot
                / screenshots（截图与填充脚本）/ visual（像素级量测）/ verify-visual.sh
docs/           主题文档（架构与约定 / 验证手册 / 踩坑与排错 / 推送与部署）
```

> 每个文件的职责、分层规则、加模块与加算法的步骤见 **`docs/架构与约定.md`**（权威版）；
> 本文件只给概览，避免两边各写一份、改了一处忘另一处。

> **`index.html` 为什么必须在仓库根**：GitHub Pages 以仓库根为发布目录，入口只能是
> `/index.html`；挪进子目录会改变公开访问路径。因此 `src/build.js` 读写路径分开：
> 读 `src/`，写 `../index.html`。

> **算法只有一份**：单纯形法的迭代内核只有 `src/core/simplex.js` 一处实现，
> 场景分析、参数线性规划、整数规划都通过 `require` 复用它（`ratioTest` / `pivot` / `solveStandardForm`），
> 不存在两份实现悄悄分叉的可能；`scenario-test.js` 的「建表一致性自检」会逐元素比对两边建的标准化矩阵。

### 分层与扩展点

```
web/*.js ──require──▶ core/{simplex,scenario,integer,format,sensitivity}
                          │
                          ├─▶ core/parse ──▶ core/model
                          ├─▶ core/{util,format,errors}
                          └─▶ core/model
```

- **单向依赖**：`web → core`，`core` 内部只允许「上层依赖下层」，没有任何环；
  `model` 是最底层（不 import 任何东西），`format` 依赖 `util` 与无外部依赖的 `number-input`。
- **禁止跨模块碰内部变量**：每个文件只导出少量公开函数，其余变量都是文件作用域私有。
- **扩展点（开闭原则）**：迭代内核被拆成 4 个可替换的纯函数 ——
  `selectEntering(form)`（入基规则）/ `ratioTest(form, e)`（比值检验）/ `pivot(form, r, e)`（枢轴变换）/
  `solveStandardForm(form, opts)`（主循环，接受 `opts.selectEntering` 与 `opts.maxIter`）。
  要加对偶单纯形、两阶段法，只需在自己的模块里组合这几个函数，
  **不必改动 `core/simplex.js` 里任何一行数值代码**。`test/unit/simplex.test.js` 里用一个
  自定义入基规则（Bland 最小下标规则）跑通了同一道题，作为这条扩展点的回归。
- **异常在 `core/errors.js` 统一收口**：对外仍保留老契约（输入非法 → `{ok:false,message}`；
  结论 → `status` 字符串），新调用方则可以拿 `LPError(code, message, detail)` 按 `code` 分支。

### 输入与结果布局

四个模块首次使用时为空题目，均提供「载入示例」和快捷规模设置。调整规模保留交集内的数据，缩小规模会删除末尾数据；载入示例会替换当前输入。

结果按「结论 → 计算过程 → 扩展分析」阅读。单纯形法先给结论，再展示标准化和迭代过程，对偶解与灵敏度区间收进默认折叠的扩展分析；整数规划先给求解摘要，再列松弛问题与各方法过程。四个模块的计算过程均可收起，章节跳转会展开对应内容，不改变模块路由。

单纯形迭代、灵敏度分析继续迭代、整数规划的松弛问题（含分枝结点的松弛迭代）和指派矩阵步骤都提供「单步学习」。默认显示完整过程；切换后一次显示一步，可前后查看或直接选择步骤，切回完整过程会保留学习位置，重新求解则从头开始。整数规划的割平面、隐枚举报告和参数线性规划的分段表仍按完整过程阅读。

四个模块共用分数输入规则：分子、分母可带正负号，允许除号两边留空格，分母不能为零；不接受混合数或算术表达式。分数在求解前转换为数值，计算沿用现有浮点算法，结果优先显示可识别的分数。

每个模块自动保存当前正在编辑的一道题，再次在同一浏览器打开此页面时恢复输入。保存内容包括未完成的数字、整数变量类型和指派的禁止标记；灵敏度变化条件在重新求基准解后恢复。计算结果不保存，恢复后需重新求解。「清空题目」会清除本模块输入、结果和已保存的题目，不影响其他模块及主题设置。

输入区的「历史记录」保留本模块最近 20 道已求解的题目，重复求解同一道题会更新记录时间并移到最前。灵敏度分析同时记录基准求解和成功执行的变化分析。可以恢复、逐条删除或清空本模块记录；恢复会替换当前输入、清除旧结果并自动保存为当前题目，重新求解后查看结果。历史记录与当前题目使用相同的版本化 `localStorage` 存储方式，各自独立；清空当前题目不会删除历史。数据仅保存在当前浏览器，清除浏览器数据会删除草稿和历史，存储不可用或写入失败时界面会提示。

视觉参考 Apple 设置与系统工具，使用实色分组面板、清晰的系统字体和蓝色主操作，并提供浅色与深色主题。样式按 `tokens.css → components.css → theme.css → workspace.css` 内联，仍可单文件离线运行。视觉规范见 `DESIGN.md`，详细分层见 `docs/架构与约定.md`。

## 关于正确性

线性规划求解器的错误往往很隐蔽——绝大多数题都能算出“看起来对”的答案。因此本项目用多道独立关卡验证：

1. **算法层**：2000 道随机题（刻意混入高比例 `≥`/`=` 约束与负右端项）与 scipy 的 HiGHS 求解器对拍，**目标值、问题状态、解向量可行性三层全部一致**。
   > ⚠️ 但**裁判也会错**：HiGHS 的 presolve 会把「无界」误判成「无可行解」（默认就开着 presolve）。
   > 场景对拍曾出现求解器状态分歧，经可行射线验证确认本项目的判定正确；最小实例、求解器对照与复核流程见 `docs/验证手册.md` 第 6 节。
   > 所以对拍脚本在两边状态不一致时会**关掉 presolve 复核**，并把这种「裁判伪影」单独打印出来，既不计失败也不隐藏。
2. **行为快照**：`test/algorithm/deep-snapshot.js` 把每道题的**每一次迭代、每一个表格格子、每一段显示文本**都哈希成一个指纹。重构前后各跑一次、`diff` 为空，就等于「算法行为逐字节未变」——这比只比最终答案严格得多（迭代方向写反、边界条件给错都可能碰巧给出同一个最优值）。
3. **单元测试**：`test/unit/` 逐模块验接口与数学性质 —— 例如对偶解不写死数字，而是用**中心差分扰动**独立验算「影子价格 = 最优值对右端项的偏导数」；σ 行不抄实现，而是在测试里**独立重算** `c_j − c_B·P_j` 再核对。
4. **界面层**：Chrome 无头浏览器在真实手机视口下跑 输入、结果与路由回归，覆盖路由、标准化、图解法、对偶解、灵敏度区间、场景分析、技术系数、参数线性规划、整数规划四方法、退化提示、0 变量/0 约束等边界与输入交互，验证渲染正确且无 JS 报错。
5. **移动端可用性**：脚本化实测所有触摸目标 ≥ 44×44、正文对比度达 WCAG AA、图解文字不越界、求解按钮无需滚动即可点到。这几项各由独立脚本把关（见上），改完随时可重跑。
6. **灵敏度区间**：区间是「恰好」的，用两道独立关口确认——① 在区间内取样，z 必须等于线性预测值（基变量用 `z₀+Δcⱼ·xⱼ`、右端项用 `z₀+Δbᵢ·yᵢ`），交给 scipy 复算；② 在区间外取样，代数上重算 `x_B` 与 σ，原最优基必须**已经失效**（否则说明区间取窄了）。
7. **场景式灵敏度分析**：判据只有一条但足够强——**场景分析给出的新最优解，必须与「把题改成新样子后用 scipy 从头重解」的结果完全一致**。120 道基准题 × 5 类场景（改 c / 改 a_ij / 改 b / 加约束 / 加变量）+ 2 个专挑基变量与非基变量下手的补例 = **700 个随机算例**，状态（最优/无可行/无界）与最优值逐项比对。
8. **参数线性规划**：结论是「λ 落在某段区间内时最优基不变，该基给出 x(λ)、z(λ)」，这句话本身要能被检验，而不是只看答案对不对（多最优解与退化会让目标值碰巧对上）。所以对每一段区间取 3 个 λ，要求：① 该段声称的最优基在这一点上**仍然可行**（`B⁻¹b(λ) ≥ 0`）且**仍然最优**（σ(λ) ≤ 0）；② 目标值等于 λ 的一次式；③ 等于从头重解的结果。再加**端点紧致性**：刚越过端点 0.05，原基必须已经失效（否则说明区间切窄了）。共 **1110 个抽样点 + 431 次紧致性检查**，全部交 scipy 独立复算。
9. **整数规划**：判据是**与暴力枚举逐项对拍**。分枝定界、割平面、隐枚举各自与「把整数变量逐个枚举、其余交单纯形法」的参考答案比对（含 0-1、纯整数、混合整数三类，各 100~400 道随机题）。

这一路验证确实揪出了若干真缺陷，都写在这里备查：

- 右端项为负的约束会被整行取负，而按标准化后的 b 算出的影子价格没有换算回用户输入，导致这类约束的符号反掉
- 最优基里残留取值为 0 的人工变量时，只要求它“≥ 0”而不要求“= 0”，会把实际上无可行解的右端项算进允许区间内
- 大 M 法在“含人工变量的扩展问题”上迭代，当入基列无正系数时不能一律判无界——若此时人工变量仍留基取正值，正确结论是**无可行解**
- 对偶单纯形的比值检验只用了检验数的常数项、忽略了 M 项，导致会挑中人工变量入基（最终答案碰巧还对，但中间解已不是原问题的可行解）
- 参数线性规划中，右端项含参数时 λ 一旦越过 `b_i(λ) = 0`，「整行取负」这个标准化动作就会翻转，而 λ 系数是按 λ = 0 的形式固定换算的 → 越界后的区间全错。修法不是硬算，而是把「标准化形式本身成立」也当成一条 λ 约束，撞上就停并说明
- 参数线性规划中，基里残留的人工变量沿着某个方向会变成正值 → 该方向上新条件无可行解，必须把这段截断在 λ = 0（与上面 b 区间那条是同一个坑的另一面）
- 整数规划隐枚举法的最小化比较方向曾有误；现将目标系数整体取负转为最大化，表头另行标明 z 使用原问题口径。

## 算法说明

采用**大 M 法**。人工变量在目标函数中罚 `-M`，`M` 以符号形式（系数对 `(常数, M 系数)`）参与运算，比较时按 `M → +∞` 的字典序进行。这样既能得到符号化的标准显示，又避免了用 `1e9` 之类大数近似带来的数值精度问题。

参数线性规划里 λ 的仿射量也用同样的「系数对」结构表示（`(常数, λ 系数)`），复用了同一套线性运算；但它与 M 不同 —— λ 是个有限的实数参数，所以比较时不能套用 `M → +∞` 的字典序，而是先解出一段 λ 区间再在端点处换基。
