# 运筹学 · 库存论 Python 计算工具

配套 **徐玖平、胡知能《运筹学（第四版）》（科学出版社 2018，ISBN 978-7-03-058397-0）第 9 章「库存论」** 的完整计算工具。
覆盖第 9 章全部 6 类模型 + 9.7 动态需求模型，共 **7 个模型**。

**零第三方依赖**（只用标准库 `math`），可直接拷到任何 Python 3.8+ 环境运行。

## 快速开始

```bash
cd python
python inventory.py          # 运行 7 道算例，打印完整计算过程（约 620 行输出）
python verify_inventory.py   # 运行独立对拍验证（1245 项检查，约 300 秒）
```

当库用：

```python
from inventory import eoq_basic, dynamic_lot_sizing

r = eoq_basic(D=10000, c1=4, c3=200, K=10, verbose=False)
print(r["Q_star"], r["C_star"])          # 1000.0  4000.0

r = dynamic_lot_sizing(demands=[20, 40, 10, 50, 30, 20], c1=1, c3=50, verbose=False)
print(r["dp"]["plan"]["orders"])          # [1, 4]
print(r["optimal_cost"])                  # 230.0
```

## 7 个模型速查

| # | 函数 | 核心公式 |
|---|---|---|
| 1 | `eoq_basic(D, c1, c3, K=None)` | Q\* = √(2Dc₃/c₁)，C\* = √(2Dc₁c₃) |
| 2 | `epq_production(D, d, p, c1, c3, K=None, periods_per_year=None)` | Q\* = √(2Dc₃/((1−d/p)c₁))，S\* = (1−d/p)Q\* |
| 3 | `eoq_shortage(D, c1, c2, c3, K=None)` | Q\* = √(2Dc₃(c₁+c₂)/(c₁c₂))，B\* = c₁/(c₁+c₂)·Q\* |
| 4 | `newsvendor(k, h, kind='discrete'\|'normal', …)` | F(Q\*) = k/(k+h) |
| 5 | `quantity_discount(D, c3, breaks, c1=None, holding_rate=None)` | 逐档 Q_i\* 可行性校验 + 计入采购费比较 |
| 6 | `multiproduct_constrained(items, constraint='capital'\|'volume', limit, …)` | Q_i(λ) = √(2c₃ᵢDᵢ/(c₁ᵢ+2λgᵢ))，二分法求 λ |
| 7 | `dynamic_lot_sizing(demands, c1, c3, initial_inventory=0, method='all')` | f(t) = min_j{f(j−1)+z(j,t)}，z(j,t) = c₃ + c₁·Σ(i−j)dᵢ |

每个函数都：
* 接收结构化参数 → 返回 `dict`（`verbose=False` 时不打印，当库用）
* `verbose=True`（默认）打印完整计算过程：参数 → 公式 → 逐步计算 → 结果 → 解读
* 对异常输入（负需求、零成本、约束不可行、单位口径不一致等）抛 `InventoryError`，带中文提示

### 几个易错点（代码里已处理）

* **模型 2 的单位口径**：D、d、p 必须同一时间口径，D = d × n。
  给 `periods_per_year` 会强制校验；n < 1 直接报错（那说明口径必然串了）。
* **模型 3 的变化方向**（别记反）：c₂ ↑ → Q\* ↓、S\* ↑、**C\* ↑**，
  且 C\* 的上限恰是 EOQ 费用 —— 允许缺货只会省钱。
* **模型 4 的离散情形**：取**首次**达到临界比的 Q（不是最接近的）；
  若 F(Q\*) 恰好等于临界比，则 Q\* 与下一档同样最优（代码会标 `exact_tie`）。
* **模型 5 必须计入采购费 D·Kᵢ** 才能比较各档，否则结论会错；
  最优解常常是某个价格分界点，而不是任何一档的 EOQ。
* **模型 6 的 λ\*** 是该项资源的影子价格（资源上限放宽 1 单位，总费用降 λ\*）。
* **模型 7 的零需求区段**：若某区段内各期净需求全为 0，该区段不需要订货、费用为 0
  （不是一次订货费）。这个坑在需求均匀的 EOQ 类模型里不存在。

## 验证

```bash
python verify_inventory.py     # 退出码 0 = 全通过
```

**原则：绝不用模型自己的公式验证模型自己。** 每个闭式解都与一个独立方法对拍：

| 模型 | 独立方法 | 规模 | 实测最大偏差 |
|---|---|---|---|
| 1 EOQ | 一维数值极小化（Brent）+ 费用结构自检 | 300 例 | Q\* 1.9e-08 |
| 2 EPQ | 一维极小化 + 数值积分锯齿库存验证 S\*/2 | 250 例 | Q\* 2.9e-08 |
| 3 缺货 | (Q,S) 二维极小化（Nelder-Mead，多起点） | 250 例 | Q\* 1.4e-08 |
| 4 报童离散 | 对 Q 穷举，期望成本按定义求和 | 250 例 | 0（完全一致） |
| 4 报童正态 | 期望成本用自适应数值积分（±∞） | 250 例 | C\* 2.7e-15 |
| 5 折扣 | 逐档密集扫描精确分段费用（不用"凸性⇒端点") | 200 例 | 费用 2.0e-08 |
| 6 多产品 | SLSQP + KKT 残差 + 影子价格中心差分 + 随机扰动 | 150 例 | KKT 5.4e-15 |
| 7 动态需求 | **全划分穷举** + **库存状态 DP**（两种独立建模） | 150 + 80 例 | 2.1e-16 |

外加：跨模型退化一致性 11 条、参数校验 40 个异常输入、手算例逐项复核。
合计 **1245 项检查**。

### 开发过程中抓到的真缺陷（值得传给下一个维护者）

1. **模型 2 允许 D 与 d 单位口径不一致**（接口设计缺陷）
   症状：随机对拍 Q\* 偏差 127%。根因：目标函数里订货费按 D、存贮费按 d 导出的
   锯齿面积算，只有两者同口径才成立，但函数签名不校验。
   修法：加 `periods_per_year` 严格校验 + `D/d < 1` 直接报错。

2. **模型 3 的性质方向写反**（文档错误）
   初版文档与测试都写"C\* 随 c₂ 单调递减"，实际是**递增**（上限为 EOQ 费用）。
   是验证套件的断言失败暴露了它。

3. **模型 7 把零净需求区段当成"要订一次货"**（算法缺陷）
   症状：模型内部的"DP 递推值 vs 按计划重算值"一致性自检失败，
   差值恰好是 2 倍（多算了订货费）。
   修法：区段累计净需求为 0 时费用按 0 计。修完由**全划分穷举**和
   **库存状态 DP** 两个独立方法共同确认（偏差 2.1e-16）。
   ⚠ 注意：那次穷举脚本本身也有同样的错，**两个都错了才会"互相印证"** ——
   幸好第三个不受影响的建模（库存状态 DP，订货量为 0 时天然不计订货费）当了裁判。

4. **EPQ 报告的单位标注错误**：把 T\*、C\* 都标成"单位时间"，混淆了两个量纲
   （T\* 是 d、p 的时间单位，C\* 是元/年）。

### 已知的、已确认不是 bug 的现象

* `newsvendor` 正态情形 `strict` 与离散情形在概率恰好相等时取较小 Q —— 两种都最优。
* 模型 6 的 SLSQP 在量级跨度大的随机题上约 12% 会报 `Positive directional derivative`
  未收敛。这是 SLSQP 自身的数值现象：本模型解由 KKT 残差（5.4e-15）+ 随机扰动检查
  独立证明最优，SLSQP 仅作费用对拍。
* 模型 7 两种启发式的劣化（400 例实测）：Silver-Meal 取到最优 67.2%、平均劣化 2.82%、
  **最差 60.08%**；PPB 取到最优 65.0%、平均 3.35%、最差 46.74%。
  这不是实现错误，而是启发式的固有弱点：Silver-Meal 用"平均费用"判据，
  末期需求大时会被抬高、提前收手、白多付一次订货费（`verify_inventory.py` 的 7-c2
  专门固定了这个失效模式）。**考试要求最优必须用动态规划。**

## 代码约定

* **符号即参数名**：`D`、`d`、`p`、`Q`、`T`、`c1`、`c2`、`c3`、`K`、`W`、`V`，
  与符号表一一对应，不需要做变量名映射。
* **计算与展示分离**：函数体里只有数学，报告全部包在 `if verbose:` 里。
* 每个函数头标注：参数含义 + 单位 + 核心公式 + 教材对应章节。
* 中文错误提示，说明**为什么**错、怎么改（不只是"参数非法"）。
* 依赖仅标准库 `math`（正态分位函数 `norm_ppf` 自带 Acklam 逼近 + Halley 迭代，
  精度约 1e-15，不依赖 scipy）。`verify_inventory.py` 才需要 scipy。

## 扩展方式

新增一个模型：在 `inventory.py` 中间插入函数（按 `# ===...` 分节），
在 `__all__` 加名字，在 `run_examples()` 加算例。
然后在 `verify_inventory.py` 里加一节，**务必配一个独立于该公式的检验方法** —— 
只做"跑通"不算验证。

## 与网页版的关系

本工具与仓库根目录的 JS 版运筹学计算器（单纯形法 / 灵敏度分析 / 整数规划）是**两套独立实现**：
Python 版是算法蓝本与验证基准，JS 版是手机端可用的交互界面。
如需在手机上增加「库存论」模块，可直接以本文件的公式、边界条件与易错点为移植蓝本。
